# Plan: Verify Now agent reads its steps from `ce_directory_playbooks`; signup-is-the-send carve-out; tenant-aware vault resolver (t_413687a7)

Cites lesson `docs/lessons/2026-11-13-first-found-must-not-hide-the-rest.md` (latest): one shared decision must see every candidate, not the first one found. Here the vault resolver ranked only `SCC - ` names, so an `NM - ` item was invisible, and a naive widening would let an NM lookup see an SCC item. The resolver takes the tenant and filters the candidate list by tenant BEFORE ranking.

Scope change (Nate, Mike ask, 11/13): steps live in ONE place, the Directory DB, not in the local allowlist JSON. No `agent_steps` in the allowlist, no `park --agent-steps-file`.

## Build
1. `db/017_directory_playbooks.sql`: `ce_directory_playbooks` (id, domain FK `ce_directories`, task in check/create/claim/fix/verify, steps jsonb array of {text, url?, selector?}, send_is_signup bool (verify only, CHECK), source, last_proven_at, updated_at, version, unique(domain, task)). RLS on, select for signed-in (same as `ce_directories`), writes by the service key only. NOT applied by this PR.
2. `job/playbook.py`: `validate_steps` (placeholders only from {business_name} {login_email} {phone} {website} {vault_item}; text/selector: no 6+ digit run, no email, no phone, no `password:`/`pw=` assignment; url: no email, no userinfo, no code/token/password/otp query param; the 6+ digit rule is NOT applied to a url because Thumbtack's `category_pk` is an 18-digit id), `set_playbook` (validate, FK pre-check, version+1, upsert), `get_playbook`, `render`, CLI `set|show --domain --task --file [--dry-run]`.
3. `verify_send.build_prompt(..., playbook=None, values=None)`: when a rendered playbook is given, a numbered "Directory playbook" block is added. Only when `send_is_signup` is true: the signup carve-out replaces the sign-in step and the "no account creation" rule is narrowed to "only the account this playbook creates, for THIS Directory, with the vault item's login". Always: no payment, no client contact. CapSolver allowed only with the carve-out on NM, `--row verify-<request id>` so the per-row cap 3 applies. `Runtime.verify_playbook(domain)` reads the DB (any failure = no playbook = no carve-out, logged). `Runtime.tenant_values(tenant, username)` fills placeholders from the identity file and the vault item NAME; a placeholder with no value fails the build (agent never starts).
4. `job/vault_item.py`: `resolve_item(domain, items, tenant="SCC")`, `list_items(runner, tenant)` (org per tenant), CLI `--tenant`. `_tenant_items` drops every item named with another tenant's prefix before ranking. `transitions._resolve_vault_item` passes the park's client.
5. Seed file `config/playbooks/thumbtack.com.verify.json` from `playbooks/build/nm-verify-now-batch-2026-11-13.md` line 7 (placeholders, `send_is_signup` true). Applying 017 and running `playbook.py set` against prod is a separate gated write (not in this PR).
