## What is already true (read from the code at 8af12eb)
- `transitions.record_transition(client, ...)` already takes a client and a TENANTS table (SCC, NM). The live move for NM is the SCC writer when called with client NM.
- `recheck.py` is the SCC proof reader. It already picks the business per queue (`queue_biz`) and per row (`_biz_of`), reads once through `sitegate.SiteGuard`, and compares with the one comparator (`recheck.compare`).
- Gap 1: the proof writer `transitions.record_proof` hard-codes `"SCC"` in the ce_directory_status upsert and defaults the queue path to the SCC queue. `db_proof_by_directory`, `mirror_proof_quiet` and `mirror_proof_file` read `biz=eq.SCC` only. Read on the real NM queue file: 4 live NM rows (n49, brownbook, manta, cylex) carry a queue `proof` that is the SCC proof for the same domain, copied in by `mirror_proof` (it matches by directory name, not business). That is wrong data on a live row.
- Gap 2: `recheck.compare` needs a street. The NM canonical lists its street only if a form requires it (`street_if_required`), so a listing that shows city, state and the right phone can never reach `match`. Data decides this, not a branch.
- Gap 3: NM rows were made live by the queue-only writer, so their ce_directory_status rows are not `queue_state=live`, and the ledger counts only `queue_state=live` with Proof.
