# Plan, round 2: tie the agent to the tenant's browser, not just name it (t_45fe02d4)

Cites lesson `docs/lessons/2026-11-13-a-prompt-must-name-what-the-run-did-not-reserve.md`: a prompt line is not a control. Round 1 named the port in the prompt only. Review (PR #116 @f77bc55) found four blocking defects; this plan fixes all four in one head.

1. **Env, not prose.** `Runtime.launch_agent(prompt_path, cdp=None)` sets `env["BROWSER_CDP_URL"] = cdp` (and removes any inherited value when none is given). `_agent_run` passes `tenant_browser(biz)[2]`. The sign-in and signup steps also tell the agent to pass `--cdp <url>` to vaultwarden-cli-fill.js. Tests: NM launch env carries 9334 and never 9333, SCC the reverse; prompt names `--cdp`. Mutation: drop the env line.
2. **Parse the real command line.** New `cmd_user_data_dir(cmd)` accepts `"--user-data-dir=PATH"` (quote before the flag, live 9333/9334 main processes) and `--user-data-dir="PATH"` (renderers) and unquoted. `same_profile(a, b)` folds quotes, `\` -> `/`, `normpath`, trailing slash and case explicitly, so Windows and Linux agree. Fixtures are copied from the live command lines (paths with spaces, both slash styles). Mutation: revert to the round-1 regex.
3. **CI on Linux.** `tenant_browser` builds the profile dir from `LOCALAPPDATA` (home when unset), not `os.path.expandvars("%...%")` (a no-op on Linux). The test sets `LOCALAPPDATA`, builds fake command lines from `tenant_browser()`'s own path, and a failing reuse case prints a FAIL line, not a traceback.
4. **SCC shares 9333 with build batches.** Only the build port (`chrome_keepalive.PORT`) is shared. For it `agent_browser`: (a) refuses (BrowserError, log line, `send_failed`, no agent) while a fresh build lease is held by anything other than a verify lease; (b) holds its own lease `verify:<pid>` for the whole run, refreshed every 60 s by a daemon thread (so the keepalive timer never fires under it); (c) if 9333 is not up, starts it with `chrome_keepalive.ensure_up` (detached, same build profile) and does NOT close it, because a batch may start meanwhile; the keepalive timer owns its end; (d) releases the lease only if it is still ours. NM 9334 keeps OwnedChrome and is closed after the run. Tests for each of a to d plus the lease refresh; mutations: skip the lease check, skip taking the lease.

Residual risk, stated: the lease is advisory (check then write is not atomic) and `build_runner` does not look at it before it starts. A batch that starts in the same second as an SCC run can still share 9333.

No send, no portal write, no deploy. After merge: re-render dry runs a25e00ff and 61ccf904.
